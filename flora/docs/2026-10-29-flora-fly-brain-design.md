# 플로라(고양이 대화) ↔ 초파리 신경망 연결·시각화 설계 — 2026-10-29

## 0. 한 줄
플로라가 손님의 말을 "맛본다". 달콤한 말일수록 초파리의 **당(설탕) 감각 뉴런**이 세게 자극되고, 초파리가 단맛에 주둥이를 내밀듯 회로의 하류 활동이 문턱을 넘으면 **로봇 팔이 플로라가 고른 색의 꽃으로 손을 뻗는다.** 색은 플로라(언어 모델)가 정하고, "지금 손을 뻗을 만큼 달콤한가"는 회로가 정한다. 이 매핑은 우리가 정한 규칙이지 회로가 감정을 이해한다는 뜻이 아니다 — 화면에도 그렇게 적는다.

## 1. 사실 확인 (출처)
- **FlyWire**: 성체 암컷 초파리 뇌 전체 연결체. 교정 완료 뉴런 139,255개, 시냅스 5천만 개 이상, 신경전달물질 정보 포함. Nature 2024(Dorkenwald 외). https://flywire.ai/
- **Shiu 외, Nature 2024 "A Drosophila computational brain model reveals sensorimotor processing"**: 연결체와 신경전달물질로만 만든 **leaky integrate-and-fire 전뇌 모델**. "당 감각 또는 물 감각 미각 뉴런을 활성화하면 섭식 개시에 필요한 뉴런을 정확히 예측", "섭식 영역 뉴런을 활성화해 운동뉴런 발화를 예측 → 광유전학·행동 실험으로 검증". 공개 코드 https://github.com/philshiu/Drosophila_brain_model (MIT). 예제 노트북: 오른쪽 반구 당 감각 뉴런 21개를 200Hz(또는 100Hz)로 자극하고, **주둥이 운동뉴런 MN9(FlyWire ID 720575940660219265)**의 발화율을 읽고, 뉴런을 하나씩 침묵시켜 MN9가 얼마나 줄어드는지 본다.
- **CoFlorist의 구현**(팀원 저장소, 읽음): 위 21개 당 감각 뉴런을 씨앗으로 연결 가중치 순으로 하류를 넓혀 **384개 뉴런·20,516개 연결**만 남긴 부분 회로를 Brian2로 돈다. 입력은 `stimulusHz`(0~250), `durationMs`(50~500, 기본 200), `seed`, `silenceIds`뿐. 출력은 스파이크 수, 활성 뉴런 수, 평균/하류 발화율, 상위 64 뉴런과 그 사이 연결(원형 그래프), 20칸 히스토그램, 스파이크 1,000개. 지금 매핑은 의도별 80/100/120Hz이고 `downstreamRateHz > 0`이면 "propose". README가 명시: "매핑은 앱이 정한 것, 회로가 꽃·말·감정을 이해한다는 증거가 아님".
- **MN9가 384개 안에 있는지는 미확인**(부분집합은 로컬 생성, 저장소에 없음). 없으면 `prepare_data.py`에 MN9를 고정 포함시키는 한 줄 변경으로 논문과 같은 읽기 지점을 쓸 수 있다.

## 2. 매핑 설계
### 입력: 대화 → 자극 세기 (서버가 계산해 보냄)
플로라의 답에서 이미 나오는 `emotion`과 `flower_color`를 쓴다.

| 상황 | emotion | stimulusHz | 이유 |
|---|---|---|---|
| 사랑·열정 (red) | loving | 150 | 가장 달콤한 말 |
| 기쁨·축하 (yellow) | happy, surprised | 120 | |
| 감사·차분 (white, purple) | neutral + 꽃 있음 | 90 | |
| 위로 (white) | sad | 60 | 부드럽게 |
| 꽃 없는 잡담 | 아무 것 | 20 | 회로는 거의 조용 |
| 혼란·졸림 | confused, sleepy | 40 | |
| "잠깐만/중지" | — | 0 | 즉시, 회로 안 기다림 |

`seed`는 턴 번호(재현 가능), `durationMs`는 200 고정(계산 1초 안쪽).

### 출력: 회로 활동 → 행동 (대시보드/로봇 쪽 정책)
- 읽는 값: `downstreamRateHz`(자극 안 받은 뉴런들의 평균 발화율). MN9가 포함되면 `mn9RateHz`를 우선.
- 결정: `reach`(문턱 이상 → 플로라가 고른 색 꽃으로 손 뻗기) / `offer`(중간 → 추천만 하고 한 번 더 묻기) / `wait`(낮음).
- 문턱은 실측으로 정한다: 실제 384 회로에서 0, 20, 40, …, 250Hz × seed 3개를 미리 돌려 "자극 세기 → 하류 발화율" 곡선 표를 만들고, 그 표의 중간값들로 두 문턱을 잡는다(10분 작업, 맥북의 CoFlorist 환경 필요).
- 색은 회로가 정하지 않는다. `flower_color`는 플로라의 답에서 그대로 온다.

## 3. 시각화 (CoFlorist 메인 화면, 턴마다 한 줄이 쌓이는 타임라인)
왼쪽에서 오른쪽으로 인과 순서대로 보인다.
1. **대화**: 손님 말 → 플로라 답 말풍선, 답 옆에 색 칩(흰·빨강·노랑·보라)과 꽃 이름.
2. **달콤함 계기**: 반원 게이지에 `stimulusHz`, 아래 한 줄 "기쁨 → 120Hz". 매 턴 바늘이 움직인다.
3. **회로 반응**: 지금 CoFlorist에 있는 원형 그래프(상위 64 뉴런, 당 감각 뉴런 21개는 바깥 고리로 강조, 발화율에 따라 점 크기)와 20칸 히스토그램을 그대로 쓰고, 숫자 3개(활성 뉴런 수 / 하류 발화율 / MN9 발화율)를 크게. 그 아래 결정 배지 `reach / offer / wait`.
4. **로봇**: "빨간 꽃으로 손 뻗는 중 → 집음 → 건넴" 상태와 운영자 확인 버튼(지금 CoFlorist의 배치·확인 흐름 그대로). 카메라 칸에 실제 팔.
5. **누적 스파크라인**: 대화가 이어지며 자극 세기와 하류 발화율이 어떻게 변했는지 작은 선 그래프. 시연에서 "우울 → 위로 → 기쁨"으로 말이 바뀔 때 회로가 따라 커지는 장면이 핵심 컷.
- 항상 보이는 작은 라벨: "FlyWire v630 부분 회로 384뉴런 · 매핑은 앱 정의 · Shiu 외 2024".

## 4. 코드가 가는 자리 (최소 변경)
| 어디 | 무엇 | 크기 |
|---|---|---|
| 우리 서버(hackathon-duo) | SSE 피드 `GET /d/<비밀>/events`: state/message 이벤트(CoFlorist 약속) + assistant message에 `flower`, `flower_color`, `emotion`, `stimulus_hz`(위 표로 계산) 필드 | 모듈 1개 + 시험, 1~2시간 |
| CoFlorist 포크(PR 1건) | 외부 대화 피드에서 assistant message에 `stimulus_hz`가 있으면 `brain.run({stimulusHz, seed})` 자동 호출 → 결과·결정 배지·색 칩을 그 말풍선 옆에 렌더, `flower_color`로 배치 항목 생성(운영자 확인은 그대로). 달콤함 게이지·스파크라인 추가 | 2~3시간 |
| CoFlorist 포크(선택) | `prepare_data.py`에 MN9 고정 포함, 결과에 `mn9RateHz` | 30분 + 데이터 재생성 |
| 문턱 보정 | Hz 스윕 표 만들기 | 30분 |

기기(고양이)와 펌웨어는 손대지 않는다. 플로라 대화는 이미 색을 내고 있으니 서버 쪽은 "보내는 통로"만 더하면 된다.

## 5. 대회 관점
- Physical AI 트랙 서술이 "대화 → 생물학적 회로 → 로봇 행동" 한 줄로 떨어진다. 심사 2단계의 "아이디어 참신성"과 "완성도"에 바로 닿는다.
- 영상 1분 하드웨어 장면: 손님 말 → 플로라 답(색) → 게이지·회로 → 팔이 그 색 꽃을 집는 컷.
- 정직성: 논문·FlyWire 출처와 "앱 정의 매핑" 라벨을 README와 화면에 둔다. 규칙의 "제3자 자료 라이선스 준수"(MIT, FlyWire 인용 지침)도 README에.

## 6. 확인 못 한 것
- MN9 포함 여부와 Hz 응답 곡선 — CoFlorist 환경(Brian2 .venv, Windows 스크립트 기준)이 맥북에만 있어 맥미니에서는 못 돌림. 맥에 설치하려면 setup 스크립트를 셸로 옮겨야 함.
- 로봇 자동 제어: CoFlorist 현재 설계는 운영자가 팔을 움직이고 확인 버튼을 누르는 방식. LeLab 쪽에 "색 → 집기" 자동 동작이 있는지는 별도 확인.
- 외부 모델(제미나이 음성) 병용은 규칙상 허용(원문 확인).

## 부록 — "초파리가 비트세이버/자전거" 영상의 정체 (10-29 조사, 링크는 records/20261029/agent-messages/requests/fly-sim-links-20261029.links-codex.md)
- 공통 재료는 2026년에 공개된 **MaleCNS**(수컷 초파리 중추신경계 연결체, Janelia FlyEM + Google, 뉴런 166,700개·시냅스 2,560만)와 Shiu 외 2024의 LIF 방식. 즉 CoFlorist가 쓰는 것과 같은 계열의 "배선도 그대로 돌리기"다.
- **비트세이버**(X, lyra bubbles): 배선도는 고정하고 그 활동을 읽어 게임 버튼을 누르는 **별도 학습 디코더**를 얹은 것. 작성자 스스로 "한 곡에 과적합, 다른 곡엔 안 됨"이라 밝힘. 코드·데이터 비공개.
- **자전거**: (1) Eric Rhea "Robot Brain Arcade" — 브라우저에서 도는 단순화 발화 시뮬, 도로 신호 24개 → 시각 뉴런 자극 → 특징 379개 → 작은 디코더(379→64→12 버튼)만 학습, 연결체는 동결, 키트 다운로드 가능. (2) victory-c/fly-brain — Shiu 모델을 PyTorch로 스파이크 단위까지 재현해 MaleCNS에 적용, 자전거 상태 → 감각 뉴런 발화(모델링) → 하강·운동 뉴런 42종을 디코더(학습 숫자 86개)로 조향, 연결체 불변. 주의: 자전거가 스스로 균형 잡는 속도 구간이라 디코더 기여는 "도로 이탈 방지" 정도라고 저자가 적음. 같은 저장소의 **"Fly Brain Live"**는 Shiu의 당·물·쓴맛 자극 실험을 전체 뉴런 140,638개 위치로 50ms 프레임 시각화하고 MN9 발화 여부를 FlyWire 결과와 나란히 보여 줌(우리 시각화의 상위 호환 참고. 저장소에 라이선스 표기 없음 → 코드 재사용 불가, 아이디어만).
- **flybody**(DeepMind/Janelia, Apache-2.0): 초파리 **몸** MuJoCo 모델 + 보행·비행 강화학습. 배선도와는 별개 계열.
- 연구자 해설(Patrick Mineault): 이런 영상은 "과학 산출물로 노는 것"이고, 연결체는 배선만 줄 뿐 시냅스 세기·시간상수·지연·세포 특성은 없으며, 대부분은 "무작위에 가까운 활동 + 따로 학습한 버튼 결정기"라 진짜 감각-운동 고리가 아니라고 평가. Shiu식 "연결체를 그대로 돌려 먹이 반응을 보는" 쪽이 그나마 근거 있는 축.
- **우리 설계에의 함의**: 우리는 디코더를 학습시키지 않고(시간·정직성), Shiu식 "당 감각 → 하류 활동"만 읽는다. 따라서 "회로가 결정한다"가 아니라 "회로 활동의 세기를 읽어 앱 규칙으로 배지를 정한다"로 말하는 게 맞고, 영상·README에도 그렇게 쓴다. 여유가 생기면 뉴런 위치 기반 시각화(FlyWire 좌표)를 CoFlorist의 원형 배치 대신 쓰는 것을 고려.
