# CoFlorist — 구현·시연 플로우·전체 진행표

기준일: 2026-10-25 (한국시간), 구현 버전 3. 전체 12단계 중 현재 8단계 진행 중. 현재 상태는 progress.json과 README.md를 함께 확인한다. 실제 Nemotron 추천·배치 해석·중단 처리와 한국어 음성 입력·응답을 확인했다. 실제 카메라와 물리 로봇 전달은 현장 검증이 남았다.

[실행 화면](http://localhost:4317) · [이전 목업](../output/imagegen/together-bloom-dashboard-v2.png)

이전 이미지는 디자인 참고용이다. 실제 구현은 CoFlorist 이름으로 메인·설정 두 화면으로 단순화했다. 네비게이션·기능·상태에 필요한 문구만 남긴다. 사용자 API 키는 설정에서 입력하며 서버 메모리에서만 유지한다.

**화면 설계**

- 첫 번째 사진의 실제 흰색 프레임·검은 서보·노출 배선·그리퍼가 있는 로봇과 작업대를 사용한다. 흰 꽃과 빨간 꽃이 이번 시연의 대상이다.
- 시각 스타일은 따뜻한 크림색, 짙은 초록색, 세이지색, 세리프 브랜드와 여백이다. 이름은 “CoFlorist”다.
- D4D에서는 화면 구획·단계·기록 및 프로세스 관리 구조를 참고한다. 색상은 새 참고 이미지에 맞춘다.
- 메인: 실제 꽃 작업 카메라, 대화, 작업 단계, 신경 활동, 운영자 수행 확인.
- 오른쪽: 한국어 음성 대화, 받아쓰기, 눌러 말하기, 대기 요청.
- 설정: Nebius 키·모델, 수령자·근거 대화, 카메라, 한국어 음성, Python·데이터 경로, 계산 테스트, 기록 내려받기·초기화.
- 상단: “운영자 보조 시연”과 실제 서비스 연결 상태 표시.
- 메인의 홍보 문구·설명 문단은 제거한다.
- 실제 로봇은 기존 조종 장치로 사람이 제어한다. 대시보드 대기 요청은 실제 모터를 직접 정지시키는 기능이 아니다.

**시작 전 준비**

- 수령자 프로필을 미리 선택해 “그 사람”을 특정한다. 불명확하면 확인 질문을 한다.
- 흰색·빨간색 선호를 뒷받침하는 이전 대화를 준비한다. 준비한 예시라면 “시연용 대화 기억”으로 표시한다. 근거가 없으면 취향을 만들어 내지 않고 확인한다.
- 수령자 ID, 색상 선호, 근거 대화 ID·발췌, 실제/시연용 구분을 저장하고 “근거 대화 보기”로 확인할 수 있게 한다.
- 흰 꽃과 빨간 꽃, 가벼운 줄기 홀더·슬리브 또는 밴드, 미리 검증한 파지 위치를 준비한다. 자동 묶기·포장은 이번 범위에 포함하지 않는다.
- 마지막에는 사람이 꽃다발을 받아 잡고, 운영자가 확인한 뒤 그리퍼를 놓는다. 그 실제 결과가 확인되어야 최종 완료다.

**시연안 — 총 2분 48초 목표**

첫 음성은 반드시 사용자의 선물 요청이다. 제목과 소개는 화면 자막으로 보여준다. 아래 시간은 리허설 목표이며 실제 모델·신경 계산 지연을 측정해 조정한다.

| 시간 | 대화·화면 | 운영자와 실제 로봇 | 확인할 결과 |
|---|---|---|---|
| 0:00–0:23 | 사용자: “그 사람에게 꽃을 선물하고 싶어.” → 로봇: “기존 대화내역으로 보았을 때 그 분은 흰 색과 빨간 색을 선물하는게 좋을 것 같아요.” → 사용자: “흰 꽃은 가운데 한 송이, 빨간 꽃은 오른쪽 한 송이. 설명은 짧게 해줘.” | 요청을 기다림 | 추천 근거 대화 표시, 실제 Nemotron 응답, 색·수량·위치·설명 선호 저장 |
| 0:23–0:52 | “흰 꽃 한 송이를 가운데에 놓을게요.” | 운영자가 로봇으로 흰 꽃을 잡아 준비된 홀더 가운데에 놓고 완료 입력 | 제안 → 수행 중 → 운영자 완료 확인 |
| 0:52–1:05 | “잠깐 기다려. 배치를 보고 싶어.” → “기다릴게요.” | 멈추고 다음 꽃 작업을 시작하지 않음 | 대기 상태와 중단 지점 보존 |
| 1:05–1:38 | “이제 계속해줘. 빨간 꽃을 오른쪽에 놓아줘.” | 빨간 꽃 작업 중 실제 확인한 파지 실패를 운영자가 기록 | 대상·위치·방법·실패 이유·기록 주체 저장 |
| 1:38–2:05 | “방금 놓친 위치를 피해, 다른 위치로 잡아볼게요.” | 검증한 대체 파지 방법으로 재시도해 오른쪽에 놓고 완료 입력 | 실패 경험이 다음 제안에 반영되고 실제 결과와 일치 |
| 2:05–2:37 | “이 배치가 좋아.” → “완성된 꽃다발을 건네드릴게요.” | 준비된 파지 위치를 잡아 꽃다발을 들고 사람에게 내밈 | 배치 승인 → 전달 준비 → 꽃다발 파지 → 들기 완료 → 전달 중 |
| 2:37–2:48 | 사람이 꽃다발을 받아 잡음 → 운영자 수령 확인 → “꽃다발을 전달했어요.” | 실제 수령 확인 후 그리퍼를 놓고 종료 | 수령 확인과 로봇의 놓기 완료 후 최종 완료 기록 |

실제 로봇 동작 장면을 최소 1분 확보한다. 대기 장면은 실제 움직임 시간으로 세지 않는다. 한국어 대화에는 영어 자막을 붙인다. 시연을 위해 의도적으로 준비한 실패 상황은 시연용 상황임을 밝히고 실제 관측 결과를 입력한다. 사전 계산을 재생하면 “저장된 계산 결과 재생”으로 표시한다.

**추가 구현할 기능**

- 기억 기반 추천: 선택된 수령자 → 근거 대화 조회 → Nemotron에 전달 → 추천과 근거를 화면에 표시.
- 배치 승인: “이 배치가 좋아”를 전달 승인으로 해석한다. 배치가 이후 변경되면 다시 확인한다.
- 전달 상태: 배치 승인 → 전달 준비 → 꽃다발 파지 → 들기 완료 → 전달 중 → 수령 확인 대기 → 놓기 완료 → 완료.
- 수행 확인: 모델의 완료 문장이나 화면 애니메이션만으로 실제 완료 상태를 변경하지 않는다. 운영자가 실제 결과를 입력한다.
- 대기·재개: 전달 중에도 새 작업 제안을 보류하고 작업 지점과 파지 상태를 유지한다. 실제 로봇의 정지·유지는 운영자가 처리한다.
- 기억 분리: 이전 대화·설명 선호·파지 실패 경험을 구분해 저장한다. 뇌 연결 지도를 대화 기억 저장소라고 설명하지 않는다.

**고정 기술 구조**

브라우저(한국어 음성·대시보드) → Express → SQLite에서 수령자 관련 대화 조회 → Nebius Token Factory의 NVIDIA Nemotron(언어 의도·근거 기반 응답).
Express → node:child_process.spawn → Python/Brian2(실제 FlyWire 신경 계산).
별도 행동 정책 + SQLite 경험 기록 → 작업 제안 → 운영자 수동 조종 → 결과 입력.

stdin/stdout은 JSONL, stderr는 로그에 사용한다. FlyWire 뉴런 ID는 Node/API/DB에서 문자열로 다룬다. Python 작업자는 한 개와 작업 큐 하나로 시작한다. 실제 뇌 계산 시간과 생물학적 시뮬레이션 시간을 구분한다. 신경 활동에서 꽃 작업으로의 연결 규칙은 사람이 설계한 공학적 인터페이스이며 초파리의 감정·사회인지 재현이라는 주장을 하지 않는다.

**실행 완료 기준**

- Nebius/NVIDIA: 실제 런타임 호출 성공, 사용 모델 식별과 호출 기록 확인.
- 한국어 음성: 실물 마이크·스피커로 입력/응답 확인. 텍스트 대체만으로 완료 처리하지 않음.
- 뇌 지도: 실제 연결 데이터를 사용한 계산 결과 확인. 목업 애니메이션만으로 완료 처리하지 않음.
- 추천 근거: 선택된 수령자의 대화 근거를 조회하고 실제/시연용 구분 표시.
- 운영자 수행: 실제 수동 조종과 완료/실패 입력이 기록에 일치.
- 최종 완료: 사람이 꽃다발을 받아 잡은 사실과 로봇의 놓기 완료를 확인한 뒤 기록.
- 대기 요청: 즉시 다음 작업 제안·대기열 보류. 실제 로봇은 운영자가 기존 조종 장치로 정지.
- 제출: 요구 링크·공개 라이선스·영어 안내·영상·접수 확인.
